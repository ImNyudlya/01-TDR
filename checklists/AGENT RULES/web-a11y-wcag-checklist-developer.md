# Чеклист веб-доступности — разработчик (React)

Для разработчиков и ИИ-агентов, которые реализуют дизайн-систему в коде.

Связанный файл: [для дизайнера](./web-a11y-wcag-checklist-designer.md)

| | |
| --- | --- |
| **Уровень** | WCAG 2.1 **AA** = ГОСТ Р 52872-2019 **AA** |
| **Обязательность** | База для всех продуктов на DS. Для B2G дополнительно — приказ Минцифры № 953 |
| **Отметка** | ✅ только если условие **уже видно** в коде, тесте или витрине компонентов |
| **Метки** | **M** — must-have · **N** — усиление · **если есть** — только при наличии фичи |

> Чеклист **базовой готовности DS** со стороны разработки, не полный юридический аудит сайта.

**Как читать:** общие рекомендации → общие для разработчика → применимые в коде → шлюз агента → быстрый проход.

## 1. Общие рекомендации

Правила для всей DS. Обязательны и дизайну, и разработке.

### Политика

- [ ] **M** Целевой уровень зафиксирован: WCAG 2.1 AA / ГОСТ Р 52872-2019 AA.
- [ ] **M** A11y входит в Definition of Done: без **M**-пунктов компонент не релизится.
- [ ] **M** В спеке публичного компонента есть: имя, роль, клавиатура, фокус, ошибки, контраст, текстовые альтернативы.
- [ ] **M** Проверка идёт на ключевых сценариях пользователя, не только на «пустой» витрине.
- [ ] **N** Есть реестр a11y-исключений: причина + план закрытия.

### Контент и поведение

- [ ] **M** Смысл не передаётся только цветом, формой, положением или звуком — есть текст или другой несенсорный признак.
- [ ] **M** Весь интерактив доступен с клавиатуры; нет ловушек фокуса; нет жёсткого лимита времени на нажатие клавиш.
- [ ] **M** Текст ссылок и заголовков понятен без контекста («Подробнее о тарифе», не «Подробнее»).
- [ ] **M** При смене фокуса или вводе данных контекст страницы сам не меняется (нет внезапного перехода, сабмита, модалки).
- [ ] **M · если есть** Автообновления, карусели, тосты: можно поставить на паузу / остановить / изменить частоту (кроме критичных для безопасности).
- [ ] **M · если есть** У значимого изображения/иконки/графики есть текстовая альтернатива; у декоративных — способ скрытия от вспомогательных технологий.
- [ ] **N · если есть** Видео/аудио: субтитры для речи + текстовая расшифровка/описание для информативного ролика.
- [ ] **N · если есть** CAPTCHA на русском и доступна без зрения (озвучка или альтернатива). *Для B2G по приказу № 953 — фактически M.*

### Шаблоны страниц / layout

- [ ] **M** Есть «Перейти к основному содержимому» (skip link) первым фокусируемым элементом.
- [ ] **M** Задан осмысленный title страницы/экрана.
- [ ] **M** Есть регионы: header / nav / main / footer (или ARIA-landmarks); при нескольких одинаковых — уникальные имена.
- [ ] **M** Иерархия заголовков логичная (без скачков ради стиля).
- [ ] **N** Повторяющаяся навигация и подписи одинаковых функций согласованы между экранами.

## 2. Общие для разработчика

Что должно быть верно в реализации UI, независимо от стека.

### Семантика и имя

- [ ] **M** Где возможно — нативные контролы, а не «кликабельные» контейнеры.
- [ ] **M** У каждого интерактива есть accessible name.
- [ ] **M** ARIA только если семантики HTML не хватает; роли не конфликтуют; интерактив не вложен в интерактив.
- [ ] **M** Кастомные виджеты (Tabs, Menu, Combobox, Dialog) повторяют ожидаемую клавиатуру и состояния по паттерну DS/APG.
- [ ] **M** Декор скрыт от вспомогательных технологий; у значимого контента есть текстовая альтернатива.
- [ ] **M** Задан язык интерфейса; смены языка во фрагментах помечены.
- [ ] **M** Списки и таблицы данных семантические; таблицы не используются для вёрстки.

### Клавиатура и фокус

- [ ] **M** Всё, что доступно мышью, доступно с клавиатуры.
- [ ] **M** Порядок фокуса совпадает с визуальным; положительный tabindex без причины в спеке не используется.
- [ ] **M** Есть видимый индикатор фокуса; снятие outline без замены запрещено.
- [ ] **M** Modal/Dialog: фокус внутрь → цикл внутри → Esc закрывает → фокус на триггер.
- [ ] **M** Нет keyboard trap вне модалок и осознанных редакторов.
- [ ] **M** Skip link работает и ведёт в основной контент (для layout).

### Формы, статусы, адаптивность

- [ ] **M** У поля есть видимая подпись; placeholder её не заменяет.
- [ ] **M** Для типовых полей указано назначение ввода (имя, email, телефон и т.п.), где уместно.
- [ ] **M** Ошибка связана с полем, объявляется текстом; где можно — есть подсказка, как исправить.
- [ ] **M** Обязательность объявлена текстом, не только цветом.
- [ ] **M** Статусы (успех / ошибка / загрузка / тост) доступны вспомогательным технологиям.
- [ ] **M** Зум **200%** сохраняет функции без обязательной горизонтальной прокрутки основного контента.
- [ ] **M** Пользовательский размер шрифта не ломает компонент.
- [ ] **M** Учтено уменьшение анимации (reduced motion).
- [ ] **M** Touch-цель ≥ **24×24 CSS px**.
- [ ] **N** Ручная проверка одним скринридером целевой платформы (VoiceOver / NVDA / JAWS).

### Качество поставки

- [ ] **M** На публичных компонентах есть автопроверка a11y в CI.
- [ ] **M** У сложных виджетов есть тесты на имя/роль/состояние и базовые клавиши.
- [ ] **M** В витрине компонентов видны focus / error / disabled и a11y-notes.
- [ ] **N** Визуальные регрессии включают focus ring и error-state.

## 3. Применимые в коде (React)

Как это выражается в реализации.

### Разметка и ARIA

- [ ] **M** Используются `button`, `a`, `input`, `label`, `select`, `textarea` там, где они закрывают сценарий; не `div`/`span` + `onClick` без роли и клавиатуры.
- [ ] **M** Имя задаётся текстом узла, `aria-label` или `aria-labelledby`.
- [ ] **M** Декор: `alt=""` или `aria-hidden="true"`; смысл — осмысленный `alt`.
- [ ] **M** У корня приложения/страницы есть `lang="ru"` (или актуальная локаль); у иноязычных фрагментов — свой `lang`.
- [ ] **M** Списки — `ul`/`ol`/`li`; таблицы данных — `table` + `th`/`scope`.
- [ ] **M** Кастомные виджеты используют корректные `role` и состояния (`aria-expanded`, `aria-selected`, `aria-controls` и т.д. по паттерну).

### Фокус и клавиши в коде

- [ ] **M** Стили `:focus-visible` заданы явно; `outline: none` только вместе с видимой заменой.
- [ ] **M** Нет `tabIndex={1+}` без документированной причины; для программного фокуса — `tabIndex={-1}` там, где нужно.
- [ ] **M** Dialog: focus trap + возврат фокуса на триггер реализованы в коде (своём или библиотечном) и покрыты тестом/стори.
- [ ] **M** Skip link — первый фокусируемый элемент, ведёт на `main` / элемент с `id` и `tabIndex={-1}`.

### Формы и live-регионы

- [ ] **M** `<label htmlFor>` / `aria-labelledby` связаны с контролом.
- [ ] **M** Где уместно — атрибут `autoComplete` (или эквивалент).
- [ ] **M** Ошибки: `aria-invalid` + `aria-describedby` / `aria-errormessage`.
- [ ] **M** Обязательность: текст + `aria-required` / `required`.
- [ ] **M** Статусы через `aria-live` / `role="status"` / `role="alert"` по критичности.

### Стили, единицы, CI

- [ ] **M** Типографика UI в `rem`/`em` (или токене, который от них зависит), не только в фиксированных `px` для текста.
- [ ] **M** Анимации завязаны на `prefers-reduced-motion: reduce`.
- [ ] **M** Hit-area обеспечена CSS (min-width/min-height/padding), не только визуальной иконкой 16×16.
- [ ] **M** В пакете UI подключены eslint-plugin-jsx-a11y и/или axe в CI на публичных компонентах.
- [ ] **M** Storybook (или аналог) показывает focus/error/disabled; для сложных виджетов есть interaction/a11y-тесты.

## 4. Шлюз для ИИ-агентов (код)

Агент **не закрывает задачу**, пока не выполнено:

- [ ] **M** Пройдены разделы 1–3 этого файла.
- [ ] **M** Семантика сохранена: не подменяет `button` на `div onClick`; заголовки и списки настоящие.
- [ ] **M** В коде явно заданы: accessible name, `:focus-visible`, клавиатура, reduced-motion, hit-area.
- [ ] **M** Не введены запрещённые паттерны DS (смысл только цветом; modal без focus trap/Esc; outline без замены).
- [ ] **N** К результату приложен короткий a11y-отчёт: линтер / клавиатура / скринридер.

## 5. Быстрый проход (код)

| Тема | Готово |
| --- | :---: |
| Контраст текста и UI (по токенам/стилям) | ☐ |
| Смысл не только цветом | ☐ |
| Focus visible + порядок фокуса | ☐ |
| Клавиатура end-to-end | ☐ |

| Формы: label, ошибки, статусы | ☐ |
| Зум 200% + относительная типографика | ☐ |
| Hover/focus-контент (tooltip и т.п.) | ☐ |
| Reduced motion | ☐ |
| Skip link + landmarks (если layout) | ☐ |
| CI / Storybook a11y | ☐ |

## Приложение. Нормативка

| Документ | Зачем в DS |
| --- | --- |
| ГОСТ Р 52872-2019 | Нацстандарт на базе WCAG 2.1; уровни A / AA / AAA |
| Приказ Минцифры № 953 (с 01.09.2024) | Обязателен для сайтов госорганов / ОМСУ / подведомственных |
| ГОСТ Р 70176-2022 | Доступность PDF/документов — на стороне продукта |
| ФЗ № 181-ФЗ | Общий контекст доступной среды |

Для коммерческих продуктов ГОСТ доброволен, пока не закреплён в ТЗ/договоре. «Версия для слабовидящих» **не заменяет** доступный основной UI при заявленном AA.
