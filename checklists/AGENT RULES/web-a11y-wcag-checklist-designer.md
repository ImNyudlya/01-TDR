# Чеклист веб-доступности — дизайнер (Figma)

Для дизайнеров и ИИ-агентов, которые проектируют дизайн-систему в Figma.

Связанный файл: [для разработчика](./web-a11y-wcag-checklist-developer.md)

| | |
| --- | --- |
| **Уровень** | WCAG 2.1 **AA** = ГОСТ Р 52872-2019 **AA** |
| **Обязательность** | База для всех продуктов на DS. Для B2G дополнительно — приказ Минцифры № 953 |
| **Отметка** | ✅ только если условие **уже видно** в макете, спеке или аннотации |
| **Метки** | **M** — must-have · **N** — усиление · **если есть** — только при наличии фичи |

> Чеклист **базовой готовности DS** со стороны дизайна, не полный юридический аудит сайта.

**Как читать:** общие рекомендации → общие для дизайнера → применимые в Figma → шлюз агента → быстрый проход.

## 1. Общие рекомендации

Правила для всей DS. Обязательны и дизайну, и разработке.

### Политика

- [ ] **M** Целевой уровень зафиксирован: WCAG 2.1 AA / ГОСТ Р 52872-2019 AA.
- [ ] **M** A11y входит в Definition of Done: без **M**-пунктов компонент не релизится.
- [ ] **M** В спеке публичного компонента есть: имя, роль, клавиатура, фокус, ошибки, контраст, текстовые альтернативы.
- [ ] **M** Проверка идёт на ключевых сценариях пользователя, не только на «пустой» витрине.
- [ ] **N** Есть реестр a11y-исключений: причина + план закрытия.

### Контент и поведение

- [ ] **M** Смысл не передаётся только цветом, формой, положением или звуком — есть текст или другой несенсорный признак.
- [ ] **M** Весь интерактив доступен с клавиатуры; нет ловушек фокуса; нет жёсткого лимита времени на нажатие клавиш.
- [ ] **M** Текст ссылок и заголовков понятен без контекста («Подробнее о тарифе», не «Подробнее»).
- [ ] **M** При смене фокуса или вводе данных контекст страницы сам не меняется (нет внезапного перехода, сабмита, модалки).
- [ ] **M · если есть** Автообновления, карусели, тосты: можно поставить на паузу / остановить / изменить частоту (кроме критичных для безопасности).
- [ ] **M · если есть** У значимого изображения/иконки/графики есть текстовая альтернатива; у декоративных — способ скрытия от вспомогательных технологий.
- [ ] **N · если есть** Видео/аудио: субтитры для речи + текстовая расшифровка/описание для информативного ролика.
- [ ] **N · если есть** CAPTCHA на русском и доступна без зрения (озвучка или альтернатива). *Для B2G по приказу № 953 — фактически M.*

### Шаблоны страниц / layout

- [ ] **M** Есть «Перейти к основному содержимому» (skip link) первым фокусируемым элементом.
- [ ] **M** Задан осмысленный title страницы/экрана.
- [ ] **M** Есть регионы: header / nav / main / footer (или ARIA-landmarks); при нескольких одинаковых — уникальные имена.
- [ ] **M** Иерархия заголовков логичная (без скачков ради стиля).
- [ ] **N** Повторяющаяся навигация и подписи одинаковых функций согласованы между экранами.

## 2. Общие для дизайнера

Что должно быть верно в решении, даже до выбора инструмента.

### Визуал и смысл

- [ ] **M** Контраст текста ≥ **4.5:1** (обычный) и ≥ **3:1** (крупный: ≥18pt / ≥14pt bold) — в светлой и тёмной теме.
- [ ] **M** Контраст UI и значимой графики ≥ **3:1** (иконки смысла, границы полей, графики, индикатор фокуса).
- [ ] **M** Цвет не единственный носитель статуса/ошибки/выбора: есть текст, иконка+текст или паттерн.
- [ ] **M** Focus-состояние спроектировано явно и отличимо.
- [ ] **M** UI выдерживает увеличение текста до **200%** без потери смысла.
- [ ] **M** UI выдерживает увеличенные межстрочные/межбуквенные отступы (WCAG 1.4.12) без наложений и потери контролов.

### Компоненты и сценарии

- [ ] **M** Для интерактива описаны состояния: default, hover, **focus**, active, disabled, error; при необходимости — loading / selected.
- [ ] **M** Ошибка формы: текст у поля + визуальный маркер; не только красная обводка.
- [ ] **M** Обязательное поле подписано текстом (не только красная звёздочка).
- [ ] **M** Минимальная зона нажатия ≥ **24×24 CSS px** (для primary лучше 44×44).
- [ ] **M** Tooltip / popover / меню по hover или focus: закрываются (Esc), не блокируют контент навсегда, остаются, пока нужны.
- [ ] **M** Dialog/modal: заголовок, закрытие, порядок фокуса, Esc, возврат фокуса.
- [ ] **M** Ориентация экрана не зашита как единственно возможная, если сценарий это позволяет.

### Типографика, layout, motion

- [ ] **M** UI-текст — настоящий текст, не картинка (кроме логотипа/декора).
- [ ] **M** Учтена RU-локаль: длинные подписи, переносы, рост длины строк.
- [ ] **M** На ширине контента **320 CSS px** нет потери функций и нет обязательной прокрутки сразу по двум осям (исключения: карты, сложные таблицы, канвас).
- [ ] **M** Для анимаций есть вариант reduced motion; нет вспышек чаще 3 раз/сек; смысл не только в движении.

### Handoff дизайна

- [ ] **M** В спеке: accessible name, роль, клавиши, поведение фокуса.
- [ ] **M** Icon-only кнопки имеют текстовое имя (tooltip сам по себе не заменяет имя).
- [ ] **M** Изображения помечены: significant / decorative + текст альтернативы.
- [ ] **M** Дизайн-часть чеклиста пройдена **до** передачи в разработку.

## 3. Применимые в Figma

Как это закрепляется в файле Figma.

### Токены и библиотека

- [ ] **M** Цвета текста/фона/границ/focus заведены как Variables (или Styles) и проверены на контраст в light/dark.
- [ ] **M** Отдельный токен/стиль для focus ring; в макетах он не перекрыт автолейаутом и соседними слоями.
- [ ] **M** Spacing/typography-токены допускают рост текста и text spacing без «ломания» компонента.
- [ ] **N** Есть набор Variables для high-contrast, если его ждут B2G-продукты.

### Компоненты и варианты

- [ ] **M** Состояния собраны как Variants / Component properties (включая **Focus** и **Error**), а не только разовые кадры.
- [ ] **M** Hit-area ≥ 24×24 зафиксирована в компоненте (padding / invisible hit-frame), а не «на глаз».
- [ ] **M** Формы в макете показывают связку: label + поле + текст ошибки (отдельные текстовые слои, не один flattened).
- [ ] **M** Для layout-шаблонов размечены регионы и порядок заголовков (секции/аннотации на frame).

### Аннотации и передача

- [ ] **M** В Description компонента / Dev Mode указаны: accessible name, роль, клавиши, Esc/focus-поведение.
- [ ] **M** У иконок и иллюстраций в аннотации: significant / decorative + текст alt.
- [ ] **M** Для icon-button текстовое имя записано в Description (не только в tooltip-варианте).
- [ ] **N** Контраст токенов перепроверен плагином (Contrast, Able и т.п.) перед publish библиотеки.

## 4. Шлюз для ИИ-агентов (дизайн)

Агент **не закрывает задачу**, пока не выполнено:

- [ ] **M** Пройдены разделы 1–3 этого файла.
- [ ] **M** В спеке явно заданы: hit-area, focus ring, contrast tokens, reduced-motion, accessible name.
- [ ] **M** Не введены запрещённые паттерны DS (смысл только цветом; modal без Esc/порядка фокуса; текст-картинка вместо UI-текста).
- [ ] **N** К результату приложен короткий a11y-отчёт: что проверено в макете / плагином контраста.

## 5. Быстрый проход (дизайн)

| Тема | Готово |
| --- | :---: |
| Контраст текста и UI | ☐ |
| Смысл не только цветом | ☐ |
| Focus-состояние спроектировано | ☐ |
| Состояния компонента (в т.ч. error) | ☐ |
| Формы: label + текст ошибки | ☐ |
| 320px + зум 200% + text spacing | ☐ |
| Hover/focus-контент (tooltip и т.п.) | ☐ |
| Reduced motion / без опасных вспышек | ☐ |
| Skip link + landmarks (если layout) | ☐ |
| Handoff-спека a11y в Figma | ☐ |

## Приложение. Нормативка

| Документ | Зачем в DS |
| --- | --- |
| ГОСТ Р 52872-2019 | Нацстандарт на базе WCAG 2.1; уровни A / AA / AAA |
| Приказ Минцифры № 953 (с 01.09.2024) | Обязателен для сайтов госорганов / ОМСУ / подведомственных |
| ГОСТ Р 70176-2022 | Доступность PDF/документов — на стороне продукта |
| ФЗ № 181-ФЗ | Общий контекст доступной среды |

Для коммерческих продуктов ГОСТ доброволен, пока не закреплён в ТЗ/договоре. «Версия для слабовидящих» **не заменяет** доступный основной UI при заявленном AA.
